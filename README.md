# LEASH

Zero-knowledge spending mandates for AI agents. An agent can only pay inside a secret policy
(a merchant allowlist and a per-transaction cap), even when it is prompt-injected. Every payment
carries a Noir proof that it satisfies the policy; the gateway (and optionally an EVM contract)
verifies the proof before any money moves. Only a commitment to the policy is public, never the rules.

Built for the PayPal AI Hackathon.

## Architecture

- **Noir circuit** (`circuits/src/main.nr`). Public inputs: `policy_commitment`, `amount`,
  `merchant_id_hash`, `nonce`, `recipient`. Private: `max_per_tx`, the allowlist `merkle_root`,
  `policy_salt`, `merchant_id` and its Merkle path. It checks that the private policy hashes
  (Pedersen) to the public commitment, range-checks `amount` and `max_per_tx` to 64 bits and enforces
  `amount <= max_per_tx`, binds the merchant to its public hash, proves the merchant is in the
  depth-4 allowlist tree, and range-checks `recipient` to 160 bits. Nonce and recipient are public
  inputs, so a proof is only valid for that exact nonce and payee.
- **`packages/core/policy_circuit`**: a second Noir program that computes the allowlist Merkle tree
  and policy commitment, so the TypeScript side uses exactly the circuit's Pedersen hashing.
- **`contracts/src/LeashVerifier.sol`**: the UltraHonk Solidity verifier generated by bb from the
  circuit (see [TOOLCHAIN.md](TOOLCHAIN.md)). **`contracts/src/LeashPayment.sol`** registers policy
  commitments, tracks used nonces per policy, verifies the proof with the payee address as the
  `recipient` input, and releases exactly the proven amount. Forge tests are in `contracts/test/`.
- **`packages/core` (`@leash/core`)**: policy management, prover and verifier (shelling out to
  `nargo` and `bb`), a nonce/audit store, a prompt-injection harness, the PayPal Orders client and an
  Express gateway. `POST /api/pay` checks the policy is registered, rejects reused nonces, verifies
  the proof, consumes the nonce, then releases the payment through the PayPal Orders API
  (create + capture). Other routes: `/api/health`, `/api/policies`, `/api/prove`, `/api/logs`,
  `/api/harness/run`.
- **Web dial UI (`apps/web`)**: Next.js console with a spending-limit dial, agent card, ZK proof
  indicator, prompt-injection matrix, demo runner and audit log. A verified proof whose PayPal release
  isn't configured shows "Setup Required".
- **`@leash/mcp` (`packages/leash-mcp`)**: an MCP server so an AI agent can pay through LEASH. Tools:
  `leash_policy` (public commitment only), `leash_verifier_health`, and `leash_request_payment`
  (prove and verify a payment, or return the rule it broke). If a tool or key is missing, the call
  errors; nothing is simulated.

## Setup

Requirements: Node, pnpm, Foundry (`forge`), and the pinned Noir toolchain from
[TOOLCHAIN.md](TOOLCHAIN.md): **nargo 1.0.0-beta.16** and **bb 3.0.1**, placed at `.tools/nargo` and
`.tools/bb` (or set `NARGO` / `BB`). The committed verifier and proof fixture are only valid for
those versions.

```sh
pnpm install
cp .env.example .env.local     # fill in PayPal sandbox creds and LEASH_RECIPIENT_ADDRESS
PATH="$PWD/.tools:$PATH" pnpm test   # builds core + vk, then core tests, nargo test, forge test
pnpm dev:gateway               # gateway on PORT
pnpm dev:web                   # web console on :3000
```

Regenerate the verifier and fixture with `pnpm gen:fixture` (the script refuses other tool versions).

Environment (`.env.example`): `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_ENVIRONMENT`
(defaults to `sandbox`), `PORT` / `GATEWAY_PORT`, `NEXT_PUBLIC_GATEWAY_URL`,
`LEASH_RECIPIENT_ADDRESS`, and the optional EVM target `LEASH_RPC_URL`,
`LEASH_PAYMENT_CONTRACT_ADDRESS`, `LEASH_PRIVATE_KEY`.

## Sponsor technology: PayPal

After a proof verifies, the gateway releases the payment with the PayPal Orders v2 API
(`/v2/checkout/orders`, then `/capture`), against `api-m.sandbox.paypal.com` by default or
`api-m.paypal.com` when `PAYPAL_ENVIRONMENT=live`. Without credentials, the release reports that it
isn't configured instead of faking an order.

## Limitations

- **No PayPal sandbox release has run yet.** It needs Nick's PayPal sandbox credentials
  (`PAYPAL_CLIENT_ID` / `PAYPAL_CLIENT_SECRET`). Until one completes, the PayPal path is untested
  end to end.
- The EVM contract path is optional and has only been exercised in Forge tests, not on a live chain.
- The gateway's nonce and audit store is local to one process.
- The policy is fixed to a 16-leaf (depth-4) merchant allowlist and a single per-transaction cap.
- Proving and verification depend on local `nargo` and `bb` binaries at the pinned versions.
- No demo video yet.
